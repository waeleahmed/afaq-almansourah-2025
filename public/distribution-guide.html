🚀 خطوات إنشاء نسخة جديدة للمدرسة

Steps to Create New School Instance

الطريقة الأولى: نسخة مستقلة (Recommended)

Method 1: Independent Instance (Recommended)

كل مدرسة لها:

  • قاعدة بيانات D1 منفصلة
  • حساب Cloudflare منفصل
  • رابط خاص بها (e.g., school-name.pages.dev)

المزايا:

  • ✅ استقلالية كاملة للبيانات
  • ✅ أمان أعلى
  • ✅ لا تأثير متبادل بين المدارس
  • ✅ كل مدرسة تتحكم في حسابها

الخطوات:

1. إنشاء حساب Cloudflare للمدرسة الجديدة

# ليس لديك خطوات آلية - يتم يدوياً:
1. زيارة: https://dash.cloudflare.com/sign-up
2. إنشاء حساب جديد باسم المدرسة
3. الحصول على API Token جديد

2. إعداد المشروع

# نسخ الكود الأساسي
git clone https://github.com/YOUR_USERNAME/afaq-almansourah.git school-name-eval
cd school-name-eval

# تعديل اسم المشروع
# Edit wrangler.jsonc
{
  "name": "school-name-eval",
  ...
}

# تثبيت المتطلبات
npm install

3. إنشاء قاعدة البيانات

# إنشاء قاعدة D1 جديدة
npx wrangler d1 create school-name-eval-db

# نسخ database_id وتحديث wrangler.jsonc
{
  "d1_databases": [
    {
      "binding": "DB",
      "database_name": "school-name-eval-db",
      "database_id": "PASTE_NEW_DATABASE_ID_HERE"
    }
  ]
}

# تطبيق Migrations
npx wrangler d1 migrations apply school-name-eval-db

4. تخصيص البيانات

# تعديل ملف public/static/images/logo.png (شعار المدرسة)
# تعديل اسم المدرسة في public/static/js/app.js
# البحث عن "آفاق المنصورة" واستبداله بـ "اسم المدرسة الجديدة"

5. النشر

# بناء التطبيق
npm run build

# النشر على Cloudflare Pages
npx wrangler pages deploy dist --project-name school-name-eval

# النتيجة:
# ✅ https://school-name-eval.pages.dev

6. إضافة مدير النظام الأول

# استخدام wrangler لإضافة أول مدير
npx wrangler d1 execute school-name-eval-db --command="
INSERT INTO users (username, password, full_name, user_type, email, phone)
VALUES ('admin', 'admin123', 'مدير النظام', 'admin', 'admin@school.edu.sa', '0500000000');
"

# أو من داخل التطبيق بعد النشر:
# زيارة: https://school-name-eval.pages.dev
# استخدام API /api/init-db إذا كان موجوداً

الطريقة الثانية: نسخة مشتركة (Multi-tenant)

Method 2: Shared Instance (Multi-tenant)

⚠️ Not Recommended for Production

جميع المدارس على نفس التطبيق ونفس قاعدة البيانات

  • كل مدرسة لها school_id
  • فصل البيانات بالبرمجة فقط

المزايا:

  • ✅ إدارة مركزية
  • ✅ تكلفة أقل

العيوب:

  • ❌ أمان أقل
  • ❌ إذا حدث خطأ يؤثر على الجميع
  • ❌ صعوبة في التخصيص

الخطوات: (ليست مفصلة لأنها غير موصى بها للإنتاج)

🎓 التدريب | Training Program

📚 برنامج تدريب المستخدمين:

للمدراء (Administrators) - 4 ساعات:

  1. الجلسة 1 (ساعة): مقدمة وإعداد النظام

    • فهم واجهة لوحة التحكم
    • إضافة المعلمين والطلاب
    • تخصيص المعايير

  2. الجلسة 2 (ساعة): إدارة المستخدمين والصلاحيات

    • إنشاء حسابات المدراء والمشرفين
    • تحديد الصلاحيات
    • إدارة كلمات المرور

  3. الجلسة 3 (ساعة): التقارير والتحليلات

    • عرض التقارير المختلفة
    • تحليل نقاط القوة والضعف
    • تصدير البيانات

  4. الجلسة 4 (ساعة): النسخ الاحتياطي وحل المشاكل

    • إنشاء نسخ احتياطية
    • استعادة البيانات
    • حل المشاكل الشائعة

للطلاب (Students) - ساعة واحدة:

  1. تسجيل الدخول
  2. اختيار المعلم
  3. ملء استمارة التقييم
  4. التأكيد والإرسال

للمعلمين (Teachers) - نصف ساعة:

  1. فهم عملية التقييم
  2. كيفية عرض نتائجهم (إن كان مسموحاً)
  3. تفسير التقارير

⚖️ الشروط والأحكام | Terms & Conditions

شروط الاستخدام:

  1. الترخيص:

    • ترخيص استخدام، وليس نقل ملكية
    • لا يحق إعادة البيع أو التوزيع
    • الاستخدام محصور في المدرسة المرخصة

  2. الخصوصية:

    • بيانات المدرسة خاصة بها فقط
    • لا نشارك البيانات مع أطراف ثالثة
    • يجب على المدرسة الالتزام بقوانين حماية البيانات

  3. المسؤولية:

    • نضمن عمل البرنامج حسب المواصفات
    • لا نتحمل مسؤولية سوء الاستخدام
    • يجب أخذ نسخ احتياطية دورية

  4. الإلغاء:

    • يمكن إلغاء الاشتراك قبل التجديد بـ 30 يوم
    • الرسوم المدفوعة غير قابلة للاسترداد
    • يتم إيقاف الدعم الفني بعد الإلغاء
